## Decisions (defaults; revisit in review)

1. **Module placement.** `inspection.py` gains `hazard_effect`/`path_effect` as two more public functions (added to `__all__`), following S17–S19's pattern of keeping public dispatch in `inspection.py` and moving nontrivial per-family logic into `_inspection/` submodules. A new `_inspection/_effects.py` holds the actual grid/window computation (`_hazard_grid`, `_window_exposure`, `_split_at`, the `path_effect` core), mirroring `_score.py`'s role for `permutation_importance`. `_inspection/__init__.py` gains the new submodule import (as it already re-exports `_loco, _score, _strata, _units`).

2. **`hazard_effect` signature** (design §4.1, unchanged from the design):
   ```python
   hazard_effect(estimator, X, y, *, feature, values=None, windows=8, kind="average", ids=None, cause=None) -> Bunch
   ```
   - `estimator`: any fitted `SurvivalForestTV`/`CompetingRisksForestTV`/`LandmarkSurvivalForest`/`LandmarkCompetingRisksForest` (`_family(estimator, fn="hazard_effect")`, unmodified). For a landmark estimator, `X` is the raw long frame and `y`/`ids` must be `None` (as `permutation_importance`'s landmark branch), dispatched to `_pe_landmark`-style stacked rows via `model._landmark_data(df)`; `windows` are on the horizon clock as S17–S19 established, and `ids` in the signature refers to counting-process rows only (landmark ids come from the frame).
   - `feature`: one name or index (not a unit — `hazard_effect` targets a single covariate's marginal effect, so it reuses `_units._column`, not `resolve_units`/`resolve_landmark_units`).
   - `values=None`: 20 quantiles of `X[:, feature]` (`np.quantile(Xe[:, j], np.linspace(0, 1, 20))`, deduplicated — ties can give fewer than 20).
   - **Computation** (`_inspection/_effects.py._hazard_grid`): reuses the per-window exposure `e_rm = clip(min(stop, w_m) - max(start, w_{m-1}), 0, None)` exactly as `metrics.piecewise_exponential_score`'s inner loop computes it (a new small helper `metrics._window_exposure(start, stop, w) -> (n, M)`, factored out of `piecewise_exponential_score`'s per-window loop body so both call sites share one implementation rather than two copies of the clip-and-subtract line — the loop itself stays in `piecewise_exponential_score`, since only the exposure array is shared, not the score accumulation). For each grid value `v` and window `m`: `Xr = Xe.copy(); Xr[:, feature] = v`; `H = predict(Xr)` (the estimator's own fixed-profile `predict_cumulative_hazard`/`predict_cause_cumhaz` at the window edges, i.e. `_heldout`'s existing `predict` callable reused verbatim — `hazard_effect` needs no OOB/held-out distinction beyond what `_heldout` already resolves, so it calls `_heldout` unconditionally rather than duplicating fixed-profile prediction); `rate_m = (H[:, m+1] - H[:, m]) / (w[m+1] - w[m])`; the window's value is `sum(e_rm * rate_m) / sum(e_rm)` over rows with `e_rm > 0` (rows with zero exposure in `W_m` contribute nothing — this is the "at risk in `W_m`" restriction the design's estimand names, achieved by the exposure weight itself rather than a separate risk-set mask).
   - **`support_mask (n_values, M)`:** `v` is inside `[P5, P95]` of `x_j` among rows with `e_rm > 0` in `W_m` (computed once per window from the *un-replaced* `Xe[:, feature]`, weighted by `e_rm` via `np.quantile`'s unweighted quantile on the boolean-masked subset — the design does not ask for exposure-weighted percentile boundaries, only "the rows at risk", so an unweighted quantile over the at-risk row subset is the direct reading).
   - **CR:** `H` has shape `(n, J, M+1)`; `cause=None` returns `(n_values, J, M)`, `cause=k` returns `(n_values, M)` (selecting one cause axis before the window loop, mirroring `_pe_codes`'s `cause` handling).
   - **`kind="individual"`:** returns `(n_rows, n_values, M)` per-row rates (`rate_m` above, before the exposure-weighted average), masked to `NaN` where `e_rm == 0` (a row not at risk in that window has no rate to report — `NaN`, not 0, since 0 would misrepresent "not evaluated" as "zero hazard"); `kind="average"`'s `values`/`support_mask`/`window_edges` are the exposure-weighted collapse of the same per-row array, so the design's "individual averages (exposure-weighted) to average" test is a direct consequence of computing both from one `rate_m` array, not two independent code paths.
   - **Errors:** `feature` naming the ids column (counting-process) or `"landmark"` (landmark) raises via the reused `_column`/`resolve_landmark_units`-style check; `kind` outside `{"average", "individual"}` raises; landmark `cause=None` with a survival (non-competing) landmark model is fine (no `cause` applies, same as `_pe_landmark`'s `competing` guard).

3. **`path_effect` signature** (design §4.2):
   ```python
   path_effect(estimator, X, intervals, ids, *, feature, delta, from_time, horizons, origin=None, cause=None, extrapolate="none") -> Bunch
   ```
   - **Landmark estimators raise `TypeError`** immediately in `_family`'s caller (a new explicit check at the top of `path_effect`, not a `_family` flag — `_family`'s existing `(is_landmark, competing)` tuple is reused only to detect this case; landmark models have no "path" concept per design's own wording, so this is a hard `TypeError`, not a `ValueError`, matching Python's convention for "this operation is not defined for this type" rather than "bad argument value").
   - **Clock and validation** (design's explicit ask, Codex review finding 5): `intervals`/`ids` are validated with the existing `_path_args`-style machinery — specifically, this function calls `estimator._path_args(X, intervals, ids, origin, extrapolate)` **twice conceptually** but only builds the row layout once: `_path_args` already returns `(X, start, stop, offsets, origin)` ordered by `(subject, start)` with `origin` resolved and range-checked (`first_start <= origin <= last_stop`). `path_effect` adds its own checks on top: every `horizons` value `h` must satisfy `origin_i <= from_time <= h <= last_stop_i` per subject `i`, unless `extrapolate="locf"` permits `h > last_stop_i`; `from_time < origin_i` for any subject raises `ValueError` naming the offending subject ids (from the `ids` labels in `_path_args`'s subject order, i.e. `np.unique(ids)` in first-appearance order — reusing `_path_args`'s own `cp.offsets`/`o` ordering rather than recomputing it, since `path_effect` must build the *same* per-subject row grouping `_path_args` already validated, to know which rows belong to which subject before splitting them).
   - **Row splitting at `from_time`** (design's explicit requirement, "rows straddling `from_time` are split there, covariates copied"): a new `_inspection/_effects._split_at(X, start, stop, offsets, from_time)` that, for each subject's rows (delimited by `offsets`), finds the row with `start < from_time < stop` (if any — `from_time` exactly on a boundary needs no split) and replaces it with two rows `(start, from_time)` and `(from_time, stop)`, both carrying the same covariate values as the original row (the shift is applied only to the second copy, in the next step). Subjects where `from_time` is outside every row's `(start, stop]` (i.e., `from_time` is at the very start or after the last stop) are handled by the existing `origin <= from_time <= last_stop` validation, which already excludes the "no such row" case except at exact boundaries (`from_time == start` of the first post-origin row needs no split either).
   - **The shifted path:** every row (post-split) with `start >= from_time` gets `x_j` replaced by `delta(x_j, start)` if `delta` is callable, else `x_j + delta`. Rows with `start < from_time` are unchanged. This gives two full interval sets — the original and the shifted — both passed through `predict_cumulative_hazard(..., intervals=..., ids=..., origin=..., extrapolate=...)` (survival) or `predict_cumulative_incidence`/`predict_cumulative_hazard(cause=...)` (CR), at `times=horizons`.
   - **Extrapolation beyond `last_stop`:** `extrapolate="locf"` is passed straight through to the underlying `predict_*` call (which already implements LOCF via `_path_args`'s own `extrapolate` handling) for **both** the original and shifted path — `path_effect` does not need its own LOCF logic, only to plumb the keyword through, since the two predict calls already agree on how to extend a path past its last observed row.
   - **Output:** `per_subject = shifted − original`, shape `(n_subjects, n_horizons)` (survival: `Δ F = ΔS_shifted - ΔS_original`... concretely `original_risk = 1 - predict_survival_function(...)`, `shifted_risk = 1 - predict_survival_function(shifted...)`, `per_subject = shifted_risk - original_risk`; CR: `predict_cumulative_incidence` directly, since CIF is already the risk scale, `per_subject = F_shifted - F_original`); `mean = per_subject.mean(axis=0)`; `horizons` echoed back as given (validated, not resolved from data — unlike `hazard_effect`'s `windows`, `path_effect`'s `horizons` has no "default from the estimator" case in the design).
   - **CR shape:** `cause=None` gives `(n_subjects, J, n_horizons)` (matching `predict_cumulative_incidence`'s own `causes_`-order shape), `cause=k` gives `(n_subjects, n_horizons)`.
   - **`delta=0` (or a callable returning `values` unchanged) gives exactly 0`,** a design-stated test: since the shifted path then equals the original path bit-for-bit before prediction, this holds by construction — no special-cased "delta is zero" branch is needed, just the same two `predict_*` calls scored on identical inputs (documented as a property, not implemented as a shortcut, so the code path being tested is the real one).
   - **Docstring wording (design's explicit requirement, verbatim per the Executive summary):** "Prediction along a specified covariate path. Valid when `x_j` is external (D4). Not a causal effect unless `x_j`'s effect on the hazard is unconfounded given the other covariates." with a reference to Keogh & van Geloven 2024.

4. **`metrics._window_exposure` extraction.** `piecewise_exponential_score`'s per-window loop (`metrics.py:756-761`) computes `width = hi - lo; e = clip(min(stop, hi) - max(start, lo), 0, None); in_window = ...` per window `m`. A new `metrics._window_exposure(start, stop, w) -> ndarray (n, M)` factors out just the `e` array (vectorized over all `m` at once via broadcasting: `lo, hi = w[:-1], w[1:]`; `e = clip(minimum(stop[:, None], hi) - maximum(start[:, None], lo), 0, None)`), called both by `piecewise_exponential_score` (replacing its per-`m` scalar computation with one vectorized call before the existing `for m` loop, which then indexes `e[:, m]` — a pure refactor, no behaviour change, covered by the existing PE score tests) and by `_inspection/_effects.py`'s `hazard_effect`. This is the one piece of existing code S20 touches outside `inspection.py`/`_inspection/`; flagged for the Codex plan review as a refactor-with-tests-unchanged, not a new behaviour.

   - `path_effect`: `per_subject`, `mean`, `horizons`, `id_labels` (subject order, for indexing `per_subject`'s first axis).

## Tests (`tests/test_inspection_effects.py`)
- **`hazard_effect`, oracle check:** a `SurvivalForestTV` stubbed with a known hazard `c * exp(β v)` (reusing `bench/tvc_perm_sim.py`'s `_stubbed`/`_carrier` pattern — a forest whose `forest_` is swapped for a true-hazard stub, as S17's sims already do) gives window hazards `c * exp(β v)` exactly at every grid value and window (up to floating-point tolerance), for both `kind="average"` and a hand-computed exposure-weighted check.
- **Weights equal exposures:** a 3-row hand-built fixture (explicit `start`/`stop` spanning known windows) where the exposure-weighted average is computed by hand and compared to `hazard_effect`'s output.
- **`support_mask`:** constructed data where some grid values fall outside the 5–95% range of at-risk rows in a given window but inside it in another — `support_mask` differs correctly per window.
- **`kind="individual"` averages (exposure-weighted) to `kind="average"`:** on the same fixture and grid, `(individual * e_rm).sum(0) / e_rm.sum(0) == average` (within a `NaN`-aware check, since `individual` is `NaN` where `e_rm == 0`).
- **CR:** `cause=None` gives `(n_values, J, M)`; `cause=k` matches the single-cause slice.
- **Landmark dispatch:** `hazard_effect` on a fitted `LandmarkSurvivalForest` uses `model.forest_`/the horizon clock (a spy on `_baseline_at`/`predict_cumhaz` confirms the inner forest is the target, as S19's own test does for `permutation_importance`); `feature="landmark"` raises.
- **Errors:** `feature` naming the estimator's ids column (counting-process) raises; `kind` outside `{"average", "individual"}` raises.
- **`path_effect`, `delta=0`:** exactly 0 for every subject/horizon.
- **`path_effect`, oracle check:** on an oracle `SurvivalForestTV` (stubbed with a known piecewise hazard along an external-covariate path, S3-generator-style), the result equals the analytic change in risk computed directly from the known hazard.
- **Straddling rows are split correctly:** a fixture with one row spanning `from_time`, compared against a manually pre-split equivalent fixture (two rows, same covariates, split at `from_time`) — both give identical `path_effect` output.
- **Validation errors:** `origin > from_time` for some subject raises, naming that subject's id; a `horizon` beyond the last `stop` without `extrapolate="locf"` raises; with `extrapolate="locf"` it does not.
- **CR shape and `cause` selection:** matches `predict_cumulative_incidence`'s own shape/`causes_` order on the same fixture.
- **Landmark `TypeError`:** `path_effect` on a `LandmarkSurvivalForest`/`LandmarkCompetingRisksForest` raises `TypeError`, not `ValueError`.
- **`metrics._window_exposure` (in `tests/test_metrics.py`):** matches `piecewise_exponential_score`'s pre-refactor per-window scalar computation on a hand-built fixture (a regression check for T1's refactor); the full existing PE score test suite stays green.

## Simulations (T9; rule from design §7.5, predeclared)
Reuses the R = 50 / 10-rep-pilot convention and `_stubbed`/`_carrier`/`holm_reject`/`mc_se` helpers of `bench/tvc_perm_sim.py`, and `tests/sim.py`'s S3 generator (`hazard(x0, z)`, `simulate`, `rows`, `true_survival`) for the known external-covariate hazard.
- **§7.5 `path_effect` against the true Δ risk.** For each replication: fit `SurvivalForestTV` on S3-generator training data; for a held-out test subject sample, call `path_effect` with `feature="z"`, a fixed `delta`, `from_time` at a mid-follow-up interval boundary, and `horizons` inside `[0, HORIZON]`; compute the **true** `Δ risk` at each horizon directly from `hazard(x0, z)` with `z` shifted by `delta` from `from_time` onward on the same test subjects' true covariate paths (i.e. the oracle uses the known hazard function, not a fitted model, mirroring `tests/sim.py`'s `true_survival` but with the shifted `z`).
  - Pass: `|mean bias|` (mean over replications of `path_effect`'s `mean` minus the true `Δ risk`) `≤ 0.1 * |true Δ|` at each horizon.
  - The 10-rep pilot checks the Monte Carlo SE of the bias against 1/7 of this margin, as S17–S19's own pilots do.
- A failed rule blocks the merge unless the user accepts a documented deviation.
