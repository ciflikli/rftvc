# Real-data validation plan: Rossi (TVC) + EBMT4 (CR + TVC)

Branch `feat/rc-validation`. Parent: user request 2026-09-27, before the release-readiness pass ("test on more real-life data for more robust testing before release candidate"). Not a `tvc-plan.md` slice (S16-S20 is closed); this is pre-release validation, its own plan. Follows the two existing case-study data conventions (`examples/data/cunningham_lemke.py`'s checksum-verified download-on-demand vs `tests/fixtures/pbcseq.py`'s committed CSV fixture). **Codex plan review applied (8 findings, all accepted — see Review log); this is the corrected version.**

## Why these two, not more
Picked from a wider domain search (political science leader tenure, business/reliability, ecology were also found but need heavier reshaping or aren't public-domain in a ready shape). Rossi and EBMT4 exercise the two real-data code paths S16-S20 has never run against real data: a genuine time-varying covariate on a single-event counting-process fit (Rossi), and a genuine competing-risks fit with a time-varying covariate (EBMT4) — `pbc2` already covers landmark + counting-process on real longitudinal biomarkers, `btscs` covers a real single-event TVC fit without competing risks, neither touches `CompetingRisksForestTV` on real data at all.

**Scope correction (Review log finding 1): this is an API/reshape/plausibility exercise, not a clinical or criminological validation.** Neither dataset lets us check the forest against an *established, specific* published effect with real confidence — see Decisions 3 and 4 below for what changed and why.

## Decisions

1. **Data sourcing and licence handling (corrected — finding 3).** `carData` and `mstate` are GPL >= 2; `survival` (the source of the already-committed `tests/fixtures/pbcseq.csv`) is **LGPL >= 2**, a different licence, and R's `DESCRIPTION` `License` field is a *package* licence — it is evidence, not independent confirmation of the *data's* redistribution terms. Overstating this in the original draft was finding 3. **Decision, corrected reasoning:** commit both fixtures anyway, but on a narrower, honestly-stated basis: both are small, long-published teaching datasets (Rossi: Rossi, Berk & Lenihan 1980, publicly re-distributed in `carData`, `RcmdrPlugin.survival`, and `lifelines.datasets.load_rossi()` for at least a decade with no dataset-specific restriction ever surfacing; EBMT4: the EBMT registry's de-identified teaching extract, shipped in `mstate` since 2011 and used in countless published tutorials/vignettes as freely redistributable). No dataset-specific licence terms were found stating otherwise. This is a judgement call, recorded here rather than silently assumed, and it is weaker than the pbcseq precedent it was originally compared to — flagged for the user to veto if they'd rather not commit third-party research data even under this weaker standard (see Acceptance).

2. **Rossi reshape** (new `tests/fixtures/rossi.py`, mirroring `pbcseq.py`'s module shape).
   - **Wide-to-long (off-by-one corrected — finding 5).** `emp_j` (`j = 1..52`) covers the interval `(j-1, j]` in weeks. A subject's last non-`NA` `emp` index **is** their `week` value directly (not `+1` — every subject's count of non-`NA` `emp` columns equals `week`, confirmed against the source table). For each subject, collapse consecutive weeks of equal `emp` value into one row: `start`/`stop` in weeks, `event` (`arrest`) on the last row only, covariate `employed` = that run's `emp` value, static covariates copied onto every row.
   - **No `id` column in `carData::Rossi`** (finding 6): `id` is the 1-based row order of the source table (stable, since the table is never re-sorted).
   - **Categorical covariates stay as strings in the fixture** (`race`, `mar`), encoded downstream in `examples/rc_validation.py`, not in the fixture module — matching Decision 3's EBMT4 convention and `btscs_war_duration.py`'s precedent of encoding at the fitting-script level. `race`: `black` -> 1, else -> 0 (the standard binary split used in the Rossi literature, `other` collapses into the reference category since it is a small residual class in this data, not a third meaningful level). `mar`: `married` -> 1, else -> 0.
   - `rossi_counting_process() -> pl.DataFrame`, columns `id, start, stop, event, employed, fin, age, race, wexp, mar, paro, prio, educ` (`race`/`mar`/`wexp` as their original string/binary source values, encoded later).
   - Test (`tests/fixtures/test_rossi.py`): row count per subject = number of `emp` value changes + 1; the last row's `stop` equals that subject's `week`; `event` is 1 only on the last row and only for arrested subjects; id=1 (never employed, `arrest=1`, `week=20`) gives exactly one row `(0, 20, event=1, employed=0)`.

3. **EBMT4 reshape** (new `tests/fixtures/ebmt4.py`). **Corrected throughout — findings 1 and 4; the covariate is relabeled and the time construction is fixed.**
   - **The covariate is a generic adverse event, not acute GvHD** (finding 1): `mstate`'s own EBMT4 documentation describes `ae` as an adverse event and states the dataset is simplified for illustration, not for clinical conclusions. The fixture and every downstream reference call it `ae` (matching the source column name), not `gvhd`. No graft-versus-leukemia / treatment-related-mortality literature claim is made about its expected sign (Decision 4 drops that entirely).
   - **Outcome (competing risks), time construction corrected (finding 4).** Per patient: `event = 1` (relapse) if `rel.s == 1`; `event = 2` (death without relapse) if `rel.s == 0 and srv.s == 1`; `event = 0` (censored) otherwise. **`stop = rel` in every case** — confirmed against the data, not assumed: every patient with `rel.s == 0, srv.s == 1` has `rel == srv` exactly (relapse-free-survival time and overall-survival time coincide once there is no relapse), so there is no "later death time" to reach for; the original draft's `stop = srv` branch was based on a false reading of the columns and is removed.
   - **Time-varying covariate `ae`.** Confirmed against the data (finding 4): every patient with `ae.s == 1` (an observed adverse event) has `ae < rel`, so the split point is always strictly inside `(0, stop)` when it applies — no "`ae` at or after `stop`" case exists in this data, and the fixture test asserts this invariant rather than hedging around it. Split: `(0, ae, ae_covariate=0)` then `(ae, stop, ae_covariate=1, event=terminal)` when `ae.s == 1`; a single row `(0, stop, ae_covariate=0, event=terminal)` otherwise.
   - `ebmt4_competing_risks() -> pl.DataFrame`, columns `id, start, stop, event, ae, year, agecl, proph, match` (the four baseline factor columns as their original string/factor-level values, encoded downstream as in Decision 2).
   - Test: interval count per patient is 1 or 2 per the rule above; `event` only nonzero on the last row; the invariants `rel == srv` whenever `rel.s == 0 and srv.s == 1`, and `ae < rel` whenever `ae.s == 1`, hold for every patient in the fixture (assertions over the whole table, not a single hand-picked row); patient 2 from `head(ebmt4)` (`rel.s=1, rel=422`) gives a last row with `event=1, stop=422`.

4. **Fits and comparison** (new `examples/rc_validation.py`, run by hand — not a docs case study yet, Decision 6). **Methodology corrected — finding 2 (importance is not a signed effect) and finding 7 (unspecified evaluation set).**
   - **Evaluation basis, stated explicitly (finding 7).** `permutation_importance` and `drop_column_importance` are run with `oob=True` (the library's own held-out-equivalent path, `tvc-design.md` §3.3) on the training `X, y, ids` — no separate manual holdout is built. `hazard_effect` has no OOB variant in the S20 design; it is run on the training data and reported as a descriptive, not held-out-validated, associational curve (stated in the findings doc, not silently implied to be a generalization check).
   - **Direction comes from `hazard_effect` contrasts and the Cox benchmark's coefficient signs, never from an importance number (finding 2).** `permutation_importance`/`drop_column_importance` report the *magnitude* of predictive relevance (a score drop, which does not carry a sign relative to "protective" vs "harmful") and are used only to rank which covariates matter, not which direction they push the hazard. Direction is read off (a) `hazard_effect(..., feature=j, values=[low, high])`'s window hazards at two contrasting covariate values, and (b) the sign of the matching `lifelines.CoxTimeVaryingFitter` coefficient on the same data.
   - **Rossi:** `SurvivalForestTV` (`btscs_war_duration.py`'s `forest()` defaults: `n_estimators=500, min_ids_leaf=10, random_state=0`) vs `CoxTimeVaryingFitter` on the same counting-process frame (encoded per Decision 2), exactly as `btscs_war_duration.py` already does side-by-side. `hazard_effect` contrasts on `fin` (0 vs 1), `age` (a low vs high quantile), `prio` (low vs high), `employed` (0 vs 1). **Expected directions** (the well-replicated textbook result: Rossi, Berk & Lenihan 1980, and every standard survival-analysis textbook worked example agrees on direction): `fin`, `age`, `employed` lower the hazard; `prio` raises it. `permutation_importance`/`drop_column_importance` report relevance ranking only, no sign claim.
   - **EBMT4:** `CompetingRisksForestTV` vs two cause-specific `CoxTimeVaryingFitter` fits (one per cause, censoring the other, the standard cause-specific-hazard approach — comparable to what `CompetingRisksForestTV`'s per-cause hazards target). `permutation_importance(..., cause=1)`/`cause=2` and `hazard_effect(..., cause=...)` for `ae` and the baseline covariates. **No expected-direction claim for `ae`** (finding 1 removed the clinical basis for one); the check is purely: does the fit run, are the two causes' `hazard_effect` curves for `ae` *distinguishable from each other* (evidence the forest is picking up cause-specific structure at all, not evidence of any particular clinical mechanism), and are the cause-specific Cox coefficients' signs at least directionally matched by the forest's `hazard_effect` contrast (an internal-consistency check between the two fitting methods on the same data, not a check against outside literature).
   - **A failed internal-consistency check** (forest and Cox clearly disagree in direction on the same data, same covariate, same cause) is a stop-and-report condition: investigate before writing it up, since it likely indicates a fixture or fitting-script bug rather than a genuine forest/Cox modeling difference, given both are estimating the same cause-specific hazard target.

5. **What this validates, concretely** (corrected — finding 8 removes a check that can't actually happen):
   - Does `permutation_importance`/`hazard_effect`/`drop_column_importance` run end-to-end on real (not simulated) counting-process rows: real ties in event times, real covariate correlation structure (EBMT4's `agecl`/`year`/`proph` interactions), real censoring-boundary reshape logic (Rossi's per-subject last-observed-week truncation, EBMT4's `rel == srv` / `ae < rel` invariants) — anything S16-S20's clean synthetic generators wouldn't surface. **Not** a missingness-handling check (finding 8): Decision 2's reshape truncates each subject at their last observed week before fitting, so the estimator never sees a `NaN`; this is a censoring-boundary correctness check, not a missing-data check, and Decision 5 no longer claims otherwise.
   - Does `CompetingRisksForestTV` + the S20 effects tools run on a real competing-risks dataset with a real time-varying covariate — the one combination no existing case study touches.
   - API friction: anything awkward, undocumented, or surprising while building the two fixtures and the fitting script gets written down verbatim in the findings doc (Decision 7) as raw input to the release-readiness pass — this plan does **not** fix API issues it finds; it reports them.
   - Runtime/memory sanity at realistic-but-modest real-world sizes (432 and ~2279-3413 subject-intervals) — not a formal timing benchmark like S17-S20's, just "did it run in a reasonable time on a laptop".

6. **Not a docs case study (yet).** Building a third `docs/source/case_studies/*.rst` page is out of scope here — a documentation/release-pass decision, not a validation one, and doubly so now that Decision 3/4 have scaled back what EBMT4 can honestly claim to show. `examples/rc_validation.py`'s output is a plain report (Decision 7), committed under `docs/plans/`, not under `docs/source/case_studies/`. Promoting one or both to a real case study is an explicit follow-up recommendation in the findings doc, left for the user to decide.

7. **Findings report.** `docs/plans/rc-validation-findings.md` (new file): the two fits' numbers (relevance rankings, `hazard_effect` contrast directions, forest-vs-Cox agreement), the Decision 4 checks' verdicts, and a bulleted "API friction / possible release-pass follow-ups" list. This is the plan's actual deliverable.

## Review log (Codex plan review, 2026-09-27)
All 8 findings accepted and applied above:
1. **High — EBMT4's `ae` is a generic adverse event, not acute GvHD**; `mstate`'s own docs say the data are simplified for illustration, not clinical conclusions. Fix: relabeled `ae` throughout, dropped the GvHD/graft-versus-leukemia literature claim (Decision 3, Decision 4).
2. **High — importance is not a signed effect.** Permutation/drop-column importance are score-drop magnitudes, not directional coefficients; either can be positive for a protective or harmful variable. Fix: direction now comes from `hazard_effect` contrasts and Cox coefficient signs only; importance is relevance-ranking only (Decision 4).
3. **Medium — the licence precedent conflated GPL and LGPL and overstated what a package `DESCRIPTION` licence covers.** Fix: reasoning corrected to a narrower "long-published, freely-redistributed teaching dataset, no dataset-specific restriction found" basis, flagged as weaker than the pbcseq precedent and vetoable (Decision 1, Acceptance).
4. **Medium — the "`stop=srv` for a later death time" claim was false**; `rel == srv` whenever there was no relapse, confirmed against the data, and `ae < rel` always holds when `ae.s==1`. Fix: `stop = rel` always; invariants asserted in the fixture test (Decision 3).
5. **Medium — Rossi's `week` off-by-one.** `week` is the last non-`NA` `emp` index directly, not `+1`. Fix: reshape rule corrected; the worked id=1 test example was already right and is unchanged (Decision 2).
6. **Medium — `carData::Rossi` has no `id` column and `race`/`mar` are categorical, not fit-ready.** Fix: `id` = source row order; categoricals stay as strings in the fixture, encoded in the fitting script, with an explicit binary encoding stated (Decision 2).
7. **Medium — the evaluation set for `permutation_importance`/`hazard_effect` was unspecified.** Fix: `oob=True` for permutation/drop-column importance; `hazard_effect` explicitly stated as descriptive/training-data only, no held-out claim (Decision 4).
8. **Medium — the claimed missingness-pattern validation cannot occur**, since Decision 2 truncates the `NA` tail before fitting and the estimator rejects `NaN` input. Fix: reframed as a censoring-boundary reshape-correctness check (Decision 5).
