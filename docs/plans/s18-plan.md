# S18 slice plan: `inspection.drop_column_importance` (LOCO, cross-fitted)

Branch `feat/s18-loco`. Parent: `tvc-plan.md` S18 (v2); `tvc-design.md` §3.4, §7 items 1/7b. Builds on S16 (`metrics.piecewise_exponential_score`, `event_windows`, `_baseline_at`, `baseline_cumhaz_`) and S17 (`_inspection/_units.py` unit resolution, the `_family`/`NotImplementedError` convention for landmark estimators). Reuses `model_selection.py`'s `_censor_at` and factors its inline splitter checks into a shared `_cv_folds`.
Notation: `p` units, `n_folds` CV folds, `n_seeds` refit seeds per fold, `M` windows, `J` causes, `N` = scored events (pooled over folds).

## Decisions (defaults; revisit in review)

1. **Signature** (tvc-plan S18, unchanged):
   ```python
   drop_column_importance(estimator, X, y=None, *, ids=None, cv=5, features=None, groups=None,
       scoring="pe", windows=8, alpha=0.01, cause=None, n_seeds=1, add_noise_control=False,
       random_state=None, n_jobs=None) -> Bunch
   ```
   - `estimator` is a `SurvivalForestTV` / `CompetingRisksForestTV` **template**, fitted or not: every fold clones it (`clone(estimator)`), so an already-fitted instance's forest is discarded. This differs from `permutation_importance`, which requires a fitted estimator; LOCO is a `cross_validate`-style function. `check_is_fitted` is not called on `estimator` itself.
   - `y` is required (`None` → `ValueError`, same message as `permutation_importance`, the `None` default kept for the S19 landmark signature).
   - `scoring="pe"` only; anything else → `ValueError` naming S19's landmark models (identical wording to `permutation_importance`, reused as a shared message constant `_score.PE_ONLY` or a small private helper — trivial duplication, no shared constant needed).
   - A landmark estimator → `NotImplementedError` (P2 convention, `cr-plan.md`); anything else that is not a `_BaseForestTV` → `TypeError`. `inspection._family` gains an `fn` keyword for the error text (`permutation_importance` / `drop_column_importance`) rather than a second copy.
2. **Units** (`_inspection/_units.py`, reused as-is).
   - `features` / `groups` resolve exactly as in S17 (`resolve_units`), including the "cannot overlap", "cannot name the ids column" and "features or groups, not both" errors. A unit is what one refit **drops**: `Xnum` without that unit's columns.
   - `feature_names_in_` does not exist yet (nothing is fitted at call time), so names come from parsing `X` directly (`_validation.split_frame`), not from the estimator.
3. **Input parsing** (mirrors `permutation_importance._heldout`, without the fitted-estimator check).
   - `ids_name = ids if isinstance(ids, str) else None` (captured before parsing, for the units' "not a feature" check).
   - `Xnum, names, ids_values = split_frame(X, ids)`: numeric `(n, p)` float64 array, column names (or `None`), and the ids array (or the column, if `ids` named one). `ids=None` → every row is its own id (`row_ids = arange(n)`), as in `permutation_importance`.
   - `ye, start = inspection._target(y, competing)` (reused: validates/builds the structured survival or CR array and returns `start`; `competing` from `_family`).
   - `w = inspection._windows(...)` cannot be reused verbatim (S17's version needs a fitted `estimator.event_times_`); instead **each fold's windows come from that fold's own full-model fit** (decision 6), so the top-level `windows` argument is only validated shape-wise here if it is already an array (`_check_windows`), or passed through as an int to `event_windows(full_model, windows)` per fold.
4. **`add_noise_control`** (drawn once, shared by every fold/seed for reproducibility of the *column*, not the fit).
   - `random_state` → one entropy integer (`inspection._entropy`, reused). A dedicated `np.random.Generator(np.random.PCG64(np.random.SeedSequence(entropy, spawn_key=(0,))))` draws one standard-normal column of length `n` (evaluated once, before folds, on the *original* row order); it is appended to `Xnum` as its last column before any fold split, so every fold's train/test slice includes the same noise values for its rows. `unit_names` gains `"_noise"`; `units` gains `[p]` (the appended column's index) as its own singleton unit, appended **last** so existing unit indices are unchanged.
   - `add_noise_control=False` (default): no column appended, no `"_noise"` unit.
5. **Folds** (`_cv_folds`, factored into `model_selection.py`; see Files/T1).
   - `cv` an int → `check_count(cv, "cv")` then `GroupKFold(cv)`. Any other object is used as given.
   - `_cv_folds(estimator, X, y, ids, cv)` is deliberately estimator-generic (S19 reuses it for landmark LOCO):
     - `time_split = isinstance(cv, RollingOriginSplit)` (covers `GroupTimeSplit` too, a subclass).
     - `horizon = getattr(estimator, "horizon", None)`; if `time_split and horizon is not None`, `cv.gap >= horizon` is required (the `landmark_cross_validate` check), else `ValueError`. For S18's counting-process estimators `horizon` does not exist, so this check is inert; it exists in the shared helper for S19's landmark models, which do have `horizon`.
     - The splitter's "time" input is each row's **`start`** (the counting-process analogue of a landmark's `s`: covariates are known at `start`, so administrative censoring at a cutoff on `start` is the right notion of "as seen at that calendar time"). `for fold, (train_idx, test_idx) in enumerate(cv.split(y["start"], groups=ids))`.
     - `time_split`: `cutoff = y["start"][test_idx].min()`; build a 3-column `pl.DataFrame({"start", "stop", "event"})` from `y[train_idx]` and run the existing `_censor_at(df, cutoff, start="start", stop="stop", event="event")` (reused verbatim: it already handles arbitrary `event` dtype, i.e. boolean or CR integer labels). `train_idx` is filtered to the rows `_censor_at` keeps (`y["start"][train_idx] < cutoff`, the same predicate `_censor_at` filters on), and a censored `y_train` structured array is rebuilt from the returned frame's `start`/`stop`/`event` columns (via `make_survival_y` / `make_competing_risks_y`, dispatched on `competing`).
     - Otherwise: `np.isin(ids[test_idx], ids[train_idx]).any()` → `ValueError` ("cv must keep ids disjoint ... or be a RollingOriginSplit/GroupTimeSplit", the existing message, generalised to drop the landmark-only wording); `y_train = y[train_idx]`.
     - Yields `(fold, train_idx, test_idx, y_train)`. `drop_column_importance` uses `train_idx` to slice `Xnum` (and `ids_values`) and `y_train` as the fold's training target; `test_idx` slices `Xnum`/`ye`/`ids_values` unchanged (test rows are never censored — the fold's outcome is scored as observed).
   - `landmark_cross_validate` is refactored to call `_cv_folds(model, df.select(...), None, ...)`? — **no**: `landmark_cross_validate` operates on stacked landmark rows keyed by `s`/`groups`, a different row representation (polars frame, `data.s`, `data.groups`) than the counting-process `(X, y, ids)` triple `_cv_folds` takes. Only the **checks** are shared (decision 5's bullet points), not the iteration itself. Concretely: `_cv_folds` factors out a private `_split_checks(estimator_horizon, cv) -> time_split` (the gap assertion) plus a private `_disjoint_check(ids_train, ids_test)`, and `_cv_folds` itself is the counting-process-row iterator built on top of them; `landmark_cross_validate`'s loop calls the same two small helpers instead of repeating the `isinstance(cv, RollingOriginSplit)` / gap / `np.isin` lines inline. This is less than the tvc-plan's literal wording ("`_cv_folds(estimator, X, y, ids, cv)` shared with `landmark_cross_validate`") but avoids forcing the landmark loop through a counting-process row shape it doesn't have; the S18 done note records this refinement. `landmark_cross_validate`'s own tests must stay green unchanged (no behaviour change, pure refactor of the checks it already runs).
6. **Per fold, per seed** (the refit loop).
   - Seeds: `entropy = inspection._entropy(random_state)`; fold `f`, seed `s` gets its own integer `int(np.random.SeedSequence(entropy, spawn_key=(f, s)).generate_state(1, dtype=np.uint64)[0] >> 1)` (fits in `int64`, as `_estimator._fit` expects for `random_state`), so results are reproducible and independent of `n_jobs`.
   - **Full model:** `full = clone(estimator).set_params(random_state=seed).fit(Xnum[train_idx], y_train, ids=ids_values[train_idx])`. Windows and null **come from this fit**: `w = event_windows(full, windows) if windows is an int else _check_windows(windows)`; `null = _baseline_at(full, w)` (both reused from `metrics.py`). Predictions on the test fold use the engine directly, as `permutation_importance`'s `_heldout` does (the public `predict_cumulative_hazard` also computes the Aalen–Johansen CIF, wasted here): `H_full = full.forest_.predict_cumhaz(Xnum[test_idx], w, full.aggregate, threads)` (survival) or `full.forest_.predict_cause_cumhaz(Xnum[test_idx], w, threads)` (CR).
   - **Per unit `j`:** `Xj_train = np.delete(Xnum[train_idx], units[j], axis=1)`, `Xj_test = np.delete(Xnum[test_idx], units[j], axis=1)`; `dropped = clone(estimator).set_params(random_state=seed).fit(Xj_train, y_train, ids=ids_values[train_idx])`; `H_drop = dropped.forest_.predict_cumhaz(Xj_test, w, dropped.aggregate, threads)` (survival) / `predict_cause_cumhaz` (CR). `full` and `dropped` must agree on `causes_` (both fit on the same training rows and, for CR, the same `causes` constructor param inherited from `estimator`); no re-check beyond the existing per-fit `causes_` computation.
   - **Scoring:** `S_full = piecewise_exponential_score(ye[test_idx], H_full, w, null_cumhaz=null, alpha=alpha, causes=full.causes_ if competing else None, cause=cause, ids=ids_values[test_idx], reduce="sum")`; `S_drop` likewise with `H_drop`. Both share the same `null`/`w`/`ids`, so `S_full.id_labels == S_drop.id_labels` (same rows, same call) and `N_fold = S_full.n_events == S_drop.n_events` (truncation at `w[-1]` depends only on `ye`/`w`, not on the predictions).
   - **Per-unit, per-fold, seed-averaged raw drop:** accumulate `total`, `by_window`, `by_cause`, `by_id` (all **sum**-reduce units, i.e. not yet divided by anything) of `S_full − S_drop` across the `n_seeds` full/dropped pairs, then divide by `n_seeds`. The full model's own fold score (`fold_scores[f] = S_full.total / N_fold` for the first seed, or the seed-average of `S_full.total`, per unit 7) is recorded once per fold (it does not depend on the unit).
7. **Cross-fit pooling and the result's point estimates.**
   - `N = sum_f N_fold` (pooled scored events over folds; each id is in exactly one fold, so no double count).
   - `ΔS_i` (per id, per unit): the seed-averaged raw `by_id` drop of decision 6, **pooled across folds** by concatenating each fold's `(ids_values[test_idx], drop_i)` pairs into one array indexed by the pooled `id_labels` (first-appearance order across folds, folds processed in order).
   - `importances_mean[j] = sum_i ΔS_i[j] / N` (equivalently `sum_f (S_full − S_drop).total / N`, seed-averaged); `importances_window[j] = sum_f (S_full.by_window − S_drop.by_window) / N` (seed-averaged), similarly `importances_cause`. These sum exactly as in S17 (`importances_window.sum(1) == importances_mean`, etc.), because every field uses the same pooled `N`.
   - `importances[j, f]` (the `(p, n_folds)` field of design §3.4): the **fold's own** per-event importance, `(S_full − S_drop).total / N_fold` (seed-averaged) — a diagnostic of fold-to-fold variability, on the fold's own denominator (not the pooled `N`), so it is not expected to average to `importances_mean` under unequal fold sizes.
   - `fold_scores[f] = S_full.total / N_fold` (seed-averaged): the full model's own cross-validated PE score per fold, independent of unit — a diagnostic, not used by any other field.
   - `baseline_score = sum_f S_full.total / N` (pooled, per event); `null_score = sum_f S_full.null_total / N`; `share_of_gain[j] = importances_mean[j] / (baseline_score − null_score)`, `NaN` + `UserWarning` when the gain is not positive (same tolerance rule as S17: `gain > 1e-12 * max(1, |null_score|)`).
   - **SE** (id splitters only): `importances_se[j] = std(ΔS_i[j], ddof=1) * sqrt(n_ids) / N`. Time splitters (`time_split`): `importances_se = NaN` for every unit; only `importances` (per-fold values) are meaningful, as `landmark_cross_validate` documents for its own scores. `n_ids` = the number of distinct pooled ids (`= n` when `ids=None`, since every row is its own id and every row appears in exactly one fold's test set... but a row is also excluded from other folds' *training* rows, that is fine — `n_ids` counts test-set appearances, one per id, by construction of a fold partition).
8. **Randomness recap** (refines tvc-plan Q6 the same way S17 did): the noise column's draw, the per-(fold, seed) fit seed and (S19) any landmark-specific randomness all derive from one `SeedSequence(entropy)`, spawned by disjoint, order-independent keys (`(0,)` for the noise column; `(f, s)` for fold `f` seed `s`), so results do not depend on `n_jobs` or on whether `add_noise_control` was requested (the noise column's own values are unaffected by whether other units are requested, matching S17's per-unit-stream property applied here to per-fold-seed streams).
9. **`n_jobs`** (tvc-design risk table: "LOCO wall time on large data ... `n_jobs` over fits"). Unlike `permutation_importance` (which parallelises only inside the engine's own prediction call, because unit-level joblib on top of engine threads would oversubscribe), LOCO's dominant cost is **independent full retrains**, so `n_jobs` here parallelises over the flat list of `(fold, seed, unit-or-full)` fit tasks with `joblib.Parallel(n_jobs=n_jobs, prefer="threads")` (the Rust fit releases the GIL). Each individual clone keeps **its own** `n_jobs` (inherited from the `estimator` template, typically left at the template's default); requesting both a large `drop_column_importance(n_jobs=...)` and a multi-threaded template estimator oversubscribes, and the docstring says so (mirroring the risk table's mitigation). Predictions after all fits complete are single-threaded per call (cheap relative to fitting; not parallelised further).
10. **Cost guard** (a test, not a runtime check): the number of `estimator.__class__.fit` calls equals `(p_units + 1) * n_folds * n_seeds`, where `p_units` already includes the `"_noise"` unit when `add_noise_control=True` (so the guard is a single formula, not `+1` twice).
11. **DataFrame / ids column** (as in S17, reusing `_units.resolve_units`'s `ids_column` argument):
    - the default units (`features=None`) exclude the ids column automatically (it is never one of `Xnum`'s columns once `split_frame` has pulled it out);
    - naming the ids column in `features` or `groups` raises (`_units._column`'s existing check, `ids_column=ids_name`);
    - every refit (full or dropped) uses the **same** `ids_values` array for grouping, sliced by the same `train_idx`/`test_idx` as `Xnum`, so the id partition is identical between the full and every dropped fit of a fold (nothing re-derives grouping from a name at each refit — there is no per-refit DataFrame at all, only the once-parsed `Xnum`/`ids_values` arrays, sliced and column-deleted). This sidesteps the literal "refits on a frame whose remaining names still pass `feature_names_in_` validation" reading of tvc-plan.md (there is no per-refit *frame*, named or not, only arrays): the S18 done note records this as a deliberate simplification, consistent with how `permutation_importance` already flattens DataFrame `X` to arrays once, at the top, rather than re-deriving names on every predict call.
12. **Result `Bunch`** (design §3.4 + tvc-plan, with the pooling of decision 7):
    - `importances (p, n_folds)`, `importances_mean`, `importances_se` (`NaN` for time splitters);
    - `importances_window (p, M)`, `window_edges`; `importances_cause (p, J)` or `None`;
    - `share_of_gain (p,)`, `baseline_score`, `null_score`, `fold_scores (n_folds,)`;
    - `n_events` (`N`, pooled), `n_ids`, `n_folds`, `feature_names`, `units` (as S17: column indices per unit, including `p` for `"_noise"`).
    - Not carried over from S17 (no permutation happens): `importances_std` over repeats, `importances_id`, `zero_rate_share` (reported per fold is not aggregated meaningfully; omitted from v1, revisit if a user asks), `n_unpermuted`, `n_rows_excluded`.
13. **Public surface.** `rftvc.inspection.drop_column_importance`, added to `inspection.__all__` and `api.rst`'s `rftvc.inspection` section (already `currentmodule`d for `permutation_importance`).

## Tests (`tests/test_inspection_loco.py`)
- **Oracle:** `_data(n, seed)` from `test_inspection_perm.py`'s convention (`tests.sim.simulate`/`rows`, `X = [x0, z, noise]`; imported via a local helper, not a cross-import of the perm test module) with `cv=3`, `n_seeds=2`: LOCO of `noise` has a mean within ±3 SE of 0 (`importances_se`, id splitter, seeded small `n`); LOCO of `x0` is `> 0`.
- **Groups:** `X` with an extra column `z_copy = X[:, 1]` (an exact duplicate of `z`): `features=None` (default, one unit per column) gives both `z` and `z_copy`'s single-copy LOCO with `|value| <= 0.1 * grouped`; `groups={"z_both": [z_idx, z_copy_idx]}` gives a grouped LOCO `> 0`.
- **Folds:**
  - id splitter (`GroupKFold`/default `cv=int`): every id appears in exactly one test fold (checked via `id_labels`-equivalent bookkeeping — a spy on `_cv_folds` or a direct call to it); `importances_se` finite.
  - time splitter (`RollingOriginSplit`): a spy `fit` records each fold's training `y["start"]`/`y["stop"]`, confirmed all `< cutoff`/clipped, i.e. `_censor_at`'s own contract, applied to arrays now instead of a polars frame; `importances_se` is `NaN`, `importances` (per-fold) are still finite; `gap` too small (`< 0`, since there is no `horizon` to compare against for a non-landmark estimator) is accepted (the horizon check is inert without `horizon`), documented by a passing test rather than an error.
  - any other splitter with non-disjoint ids (plain `KFold` without `groups=ids`, ids with repeats) raises the disjointness `ValueError`.
- **Consistency:** a spy on `event_windows`/`_baseline_at` (or on the recorded `w`/`null` passed to `piecewise_exponential_score`, via monkeypatching) confirms the **full** model's fit supplies `windows`/`null` and the dropped model's predictions are scored against them (not its own).
- **Seeds:** `n_seeds=2` reproducible for a fixed `random_state`; a spy `fit` count confirms exactly 2 fits per (fold, unit) (full + each dropped unit).
- **Cost guard:** total `fit` calls `== (p_units + 1) * n_folds * n_seeds`, with and without `add_noise_control=True` (`p_units` includes `"_noise"` when enabled).
- **Noise control:** `add_noise_control=True` reports a `"_noise"` unit in `feature_names`/`units` (last position); its column is standard-normal and identical across folds (drawn once, before the split) — checked via a spy on `Xnum` seen by `fit`.
- **DataFrame / ids column:** a pandas DataFrame `X` with `ids="id"` naming a column of `X`:
  - default units exclude `"id"`;
  - `features=["id"]` / `groups={"g": ["id"]}` raise;
  - the same result as the array-input case, feature-for-feature (`features=["x0", "z"]` gives the array case's `features=[0, 1]` result, same seed);
  - a spy confirms the grouping (`ids_values`) used by the full and every dropped fit of a fold is identical (decision 11).
- **`cause`:** a `CompetingRisksForestTV` scenario (the S14-style generator, small): `cause=1` restricts to cause 1 (`importances_cause` is `None`); `cause=None` gives `importances_cause` summing to `importances_mean`; an unfitted-vocabulary `cause` (not in the first fold's `causes_`) raises via `piecewise_exponential_score`'s own check (no separate pre-check needed).
- **Errors:** unknown feature name/index, feature names without column names on `X` (a bare array with `features=["x0"]`), overlapping/empty groups, `features` + `groups`, ids column as a unit, `y=None`, `scoring="brier"`, `n_seeds < 1`, `cv` not an integer `>= 1` and not a splitter-like object (duck-typed: no `.split`), a landmark estimator (`NotImplementedError`), a non-rftvc estimator (`TypeError`).

## Simulations (T6; rules from design §7.1/§7.7b, predeclared)
Reuses `bench.tvc_perm_sim.trend_data` (the §7.1 trend-confounding generator: `z1` has an effect, `z2` trends with `t` and correlates with `z1` at ρ = 0.6, plus two baseline noise columns) and `bench.tvc_perm_sim.trend_oracle` (the permutation-importance oracle margin, `oracle(z1)`, already computed and validated in S17's note: 0.617). R = 50 (a 10-rep pilot checks MC SE ≤ margin / 7, as S17).

1. **§7.1 LOCO part.** `drop_column_importance(model, Xt, yt, ids=idt, cv=5, features=[0, 1], n_bootstrap=...)` — no bootstrap parameter exists for LOCO; `n_seeds=1` (fit noise is not the object of this check). 1000 training ids used as the cross-fitting sample (5 folds of 200 ids each; a fresh 1000-id sample per replication, as `trend_replicate` already draws).
   - Pass (design §7.1, as declared): `|mean imp(z2)| ≤ 0.1 · oracle(z1)` (oracle from `trend_oracle()`, computed once, reused as in S17's note: 0.617, margin 0.0617).
   - Also reported (no rule, for context): `mean imp(z1)`, for comparison against the permutation-importance forest mean of 0.455 (S17 note) — LOCO's estimand differs (it can be smaller if the forest partly recovers `z1`'s signal through `z2`, since a correlated `z2` remains available when `z1` is dropped, per the design's own estimand caveat, §3.4).
2. **§7.7b null control and grouped LOCO.** Same generator (`trend_data`), `cv=5`, `n_seeds=1`, `add_noise_control=True`, `features=[0, 1]` (z1, z2 as ordinary units) plus the noise control.
   - Pass (a): the `"_noise"` unit's mean importance is within `±2` Monte Carlo SE of 0 over the R = 50 replications (SE of the *mean across replications*, i.e. `std(replicate values, ddof=1) / sqrt(R)`, not the per-replication `importances_se`).
   - Pass (b), **grouped vs. single copy** (design §7.7b's second sentence): a duplicated-`z1` variant of the generator (`X = [z1, z1_copy, n1, n2]`, `z1_copy = z1` exactly, hazard unchanged) — mean single-copy LOCO of `z1` and of `z1_copy` (`features=None`, one unit each) is `≤ 0.1 ×` the mean grouped LOCO (`groups={"z1_both": [0, 1]}`), and the grouped mean is `> 0` (a one-sided t-test at 5%, uncorrected: one comparison, no Holm needed).
   - The 10-rep pilot checks the MC SE of each of (a)'s and (b)'s means against its margin (`0.1 · oracle(z1)` for (b)'s grouped/single ratio numerator's scale; a fixed `0.02` absolute margin for (a), since the null-control mean itself, not a ratio, is being bounded — chosen as roughly `0.03 · oracle(z1)`, documented in the note alongside the observed value).
- A failed rule blocks the merge unless the user accepts a documented deviation.

## Review log (self-review; no external Codex session available this turn)
Findings from a full read of `tvc-design.md` §3.4/§7, `tvc-plan.md` S18, `model_selection.py`, `inspection.py`, `_inspection/_units.py`/`_score.py`, against this plan's decisions:
1. **`_cv_folds` cannot literally be shared between counting-process LOCO and `landmark_cross_validate` as one iterator** — they iterate different row shapes (arrays vs. a polars frame keyed by `s`). Resolved (decision 5): share the two *checks* (gap-vs-horizon, disjoint ids), not the row iteration; `landmark_cross_validate` is refactored to call the shared checks, not rewritten around `_cv_folds`. Recorded as a plan-level refinement of tvc-plan's wording, the way S17 refined "`·ΣN`" to "per event" (Q8).
2. **The splitter's "time" axis for counting-process rows is unspecified in tvc-design/tvc-plan** (landmark has `s`; counting-process rows have `start`/`stop`). 7. **Found during implementation (not plan review): `RollingOriginSplit`/`GroupTimeSplit` cross-fitting is structurally near-useless for counting-process LOCO's PE score.** `_cv_folds`'s administrative censoring (decision 5) clips *every* training row's `stop` at the fold's cutoff, by design (no leakage) — so a fold's training `event_times_` (hence its `baseline_cumhaz_` and every leaf's own grid) never extends past that cutoff, and every test row's `stop` is, by construction of a "future periods" split, at or after it. Both the forest's prediction and the training null are flat (zero increment) past their own last observed event — a structural property of any Nelson–Aalen-based estimator, not a bug — so **every** window entirely beyond the cutoff scores a real event as `log(0) = -inf`, regardless of `alpha`, `n_estimators` or data size (verified: a 800-subject S3-generator smoke test gives `fold_scores = [-inf, -inf]` under `RollingOriginSplit`). This does not affect the default `cv=int` (`GroupKFold`, new-subject CV): a test *id*'s events are drawn from the same time range as training ids', so they fall well inside the training tau (verified: no degeneracy in the smoke tests below). It also does not extend to S19's landmark LOCO, whose scoring is on the *reset* clock `(0, horizon]`, not calendar time — every training landmark contributes reset-clock rows in that range regardless of calendar time, so the same structural wall does not apply there. Resolved for S18:
   - `windows` as an int under a time-based `cv` now raises `ValueError` (decision 6 amendment): no single fold's own `event_windows(n)` can define one set of edges valid for every fold's differing, always-earlier training tau, so an explicit array is required.
   - The docstring and the S18 done note state plainly that `RollingOriginSplit`/`GroupTimeSplit` are supported for API/censoring-mechanics consistency with `landmark_cross_validate` (S19 reuses the same `_cv_folds`), but are not practically useful for counting-process `drop_column_importance` today; `cv=int` (new-subject CV) is the documented, primary mode. Fixing this would need a parametric (extrapolating) baseline-hazard model, out of scope for S18 — flagged as a possible follow-up, not fixed here.
   - The "Folds" test for a time splitter is scoped to the *censoring mechanics* only (training rows correctly clipped, `importances_se` is `NaN`, the int-windows guard raises), not to a realistic (non-degenerate) importance value, which the structural limit above makes unattainable by construction.
8. **Found while running the §7.7b grouped-vs-single-copy sim: "single copy ≈ 0" is not close to a literal 0 relative to grouped.** Design §7 item 7b's own words ("each single copy is ≈0") set no numeric bound; my draft (Tests section, "Groups" bullet) had guessed `|single| ≤ 0.1 × grouped`, mirroring the §7.1 M2 rule's style. Measured at the bench sim's scale (1000 ids, 5 folds, 100–500 trees — the ratio is stable across tree counts, ruling out a forest-size artefact): single/grouped ≈ 15–23%, not ≤ 10%. This is a real, reproducible property of dropping one of two literally identical columns under `max_features="sqrt"` splitting (the surviving copy remains available to every split, so it is a *cheap*, not *free*, substitute — a duplicate column dilutes its own selection frequency, and removing one can even marginally help generalisation, hence the small but non-negligible, sometimes negative, single-copy values observed). Resolved: the fast unit test's bound is loosened to `≤ 0.5 × grouped` (comfortably covers the observed range with headroom, while still asserting "clearly smaller than half of grouped"); the bench sim's only *gated* pass rule is "grouped mean > 0" (a one-sided t-test, the part of design §7b's sentence that is a comparison against a known-zero baseline and holds cleanly and significantly); the single-copy/grouped ratio is reported for interpretive value, not gated on, the same way the §7.1 estimand caveat is reported without a pass rule.
