# S19 slice plan: landmark importance + history features

Branch `feat/s19-landmark-importance`. Parent: `tvc-plan.md` S19 (v2); `tvc-design.md` §3 (landmark bullets), §5, §6 (CR), §7.2/§7.5b. Builds on S17 (`_inspection/_units.py` unit resolution, `_strata.py` binning/donors, `_score.py`'s `Evaluation`/`Strata`/`unit_importance`/`score` core, the `_family` dispatch convention) and S18 (`_cv_folds`'s shared `_split_checks`/`_disjoint_check`, the LOCO refit-loop shape in `_inspection/_loco.py`). Reuses `metrics.piecewise_exponential_score`/`event_windows`/`_baseline_at` (on the landmark's *inner* forest, fit on stacked rows, so these already speak the reset clock) and `model_selection._score_landmark`/`brier_landmark`/`integrated_brier`/`KaplanMeierCensoring`.
Notation: `p` units (raw columns by default), `M` PE windows, `J` causes, `S` landmark grid, `N`/`n` scored events/rows (per scoring family, defined per decision).

## Decisions (defaults; revisit in review)

1. **Signature** (tvc-plan S19 reuses the shared S17/S18 signatures unchanged, plus two scoring-family-only keywords):
   ```python
   permutation_importance(estimator, X, y=None, *, ids=None, features=None, groups=None,
       strata="time", n_strata=10, conditional_on=None, n_bins=4,
       scoring="pe", windows=8, alpha=0.01, cause=None,
       oob=False, n_repeats=5, n_bootstrap=100, random_state=None, n_jobs=None,
       censoring_estimator=None, g_min=0.05, n_times=10) -> Bunch

   drop_column_importance(estimator, X, y=None, *, ids=None, cv=5, features=None, groups=None,
       scoring="pe", windows=8, alpha=0.01, cause=None, n_seeds=1, add_noise_control=False,
       random_state=None, n_jobs=None, censoring_estimator=None, g_min=0.05, n_times=10) -> Bunch
   ```
   - `estimator` a `LandmarkSurvivalForest` / `LandmarkCompetingRisksForest`: `X` is the raw long frame `df` (`y`, `ids`, `oob` are rejected — `oob=True` → `ValueError` naming counting-process-only; `ids` given → `ValueError`, since ids come from `df`'s own id column, `model.id`; `y` must be `None`, else `ValueError`, the reverse of the counting-process check). `permutation_importance` still requires a **fitted** `estimator` (`check_is_fitted(estimator, "forest_")`, unchanged); `drop_column_importance`'s `estimator` is a template as in S18 (fitted or not; every fold clones and re-fits it, including its `history_features`/`landmarks`/`step`/`forest` params).
   - `censoring_estimator`, `g_min`, `n_times`: new, keyword-only, **valid only for landmark `scoring in {"brier", "ibs"}`**; passing any of them (away from their defaults, or at all — see decision 9's exact rule) with `scoring="pe"` or with a counting-process estimator raises `ValueError`. Same names/defaults/semantics as `landmark_cross_validate`/`metrics.brier_landmark`/`metrics.integrated_brier`.
   - `_family` (`inspection.py`) drops its landmark `NotImplementedError` and gains a third branch: `isinstance(estimator, _LandmarkBase)` → `(True, competing)` instead of `(competing,)`, so every call site knows which frame-shape branch to take. `fitted=True` still calls `check_is_fitted` for `permutation_importance`; `drop_column_importance` keeps `fitted=False`.
2. **Aggregations** (`landmark.py`, tvc-design §5 / T8).
   - `AGGREGATIONS = ("last", "first", "mean", "min", "max", "sum", "count", "slope", "std")`.
   - `_agg_expr` gains a `time` parameter (the OLS time axis for `"slope"`): callers pass `measured_at if measured_at is not None else start` (a column **name**, not a per-row array — the existing `_history_features(df, s, specs, *, id, start)` signature gains `measured_at=None` and threads `time = measured_at or start` into `_agg_expr`, changing its call sites in both `make_landmark_data` and `landmark_features`; `_agg_expr`'s existing `start` parameter keeps its current job, ordering `"last"`/`"first"` — the two column roles are independent, matching the design's own wording ("slope on `measured_at`, or on `start` when there is no `measured_at`") without touching how `"last"`/`"first"` already sort).
   - `"slope"`: `pl.when(pl.col(time).n_unique() < 2).then(None).otherwise(pl.cov(pl.col(time).cast(pl.Float64), col) / pl.col(time).cast(pl.Float64).var())`. Polars' population-vs-sample `var`/`cov` ratio is scale-invariant (both use the same `ddof`), so the OLS-slope identity `cov(t, y) / var(t)` holds regardless of which `ddof` polars defaults to; the explicit `n_unique < 2` guard exists because a single distinct time gives `var = 0` (which would otherwise divide to `inf`/`NaN` inconsistently across polars versions) — this matches "NaN with fewer than 2 distinct times" literally, not "whatever a 0/0 division happens to produce".
   - `"std"`: `col.std()` (polars' default `ddof=1`); a group of 1 row already gives a polars `null`, which the existing `.to_numpy().astype(np.float64)` conversion at the end of `make_landmark_data`/`landmark_features` turns into `NaN` for free (the same path every other aggregation's `null` already goes through — no special-case needed).
   - Both new names are just entries in the existing `exprs` dict inside `_agg_expr`; no other function in `landmark.py` branches on the aggregation name.
3. **Raw-column groups** (`landmark.py`, new `_raw_groups(history_features)`).
   - `_raw_groups(history_features) -> dict[str, list[str]]`: reuses `_feature_specs(history_features, forbidden=set())` (the same parser `make_landmark_data` already runs; `forbidden=set()` because the forbidden-lookahead check is a *fit-time* concern already enforced once and `_raw_groups` only re-derives names from an already-validated, already-fitted model's `history_features`) and groups the resulting `(name, column, agg)` triples by `column`, preserving first-appearance order of both columns and names within a column (`{"z": ["z", "z_mean", "z_slope"], "x": ["x"]}` for `history_features=["z", ("z", "mean"), ("z", "slope"), "x"]`, matching tvc-plan's own worked example). `"landmark"` never appears (it is not in `history_features`, only appended by `make_landmark_data`/`landmark_features` afterward), which is exactly the "not a permutable unit" property — for free, not by a special case.
4. **Units** (new `_units.resolve_landmark_units(features, groups, raw_groups, names, n_features)`, alongside the existing `resolve_units`, both exported from `_inspection/_units.py`).
   - `features` and `groups` together → `ValueError` (unchanged rule).
   - `groups` given: delegates to the existing `resolve_units(None, groups, names, n_features, ids_column="landmark")` verbatim — a landmark user-defined group is exactly the S17 mechanism (arbitrary jointly-permuted column sets), and reusing `ids_column="landmark"` rejects a group naming the `"landmark"` column with `resolve_units`'s existing "is the ids column, not a feature" message. This message's wording is imprecise here (`"landmark"` is not an id column) — accepted as a small, documented wording debt rather than forking `_column`'s error text for one extra case (see review log).
   - `features=None, groups=None` (the default): one unit per **raw column** of `raw_groups`, named after the raw column, columns = the sorted indices of that column's whole feature-name group in `names`. This is the M3-equivalent "variable-level" default the design calls for.
   - `features` given: each entry is either a key of `raw_groups` (a raw column — expands to that column's whole group, one unit named after the raw column) or a name/index in `names` (a single landmark feature — a singleton unit, name = the resolved column's name). A literal `"landmark"` (by name or by its index, always `n_features - 1` — `make_landmark_data`/`landmark_features` both append it last) raises `ValueError` ("'landmark' is constant within a landmark stratum and is not a permutable unit"), checked directly rather than through the `ids_column` machinery (unlike the `groups` branch, `features` entries are resolved one at a time and a dedicated message is cheap here). Two entries that resolve to overlapping columns (e.g. `features=["z", "z_mean"]`, both inside the same raw group) raise the existing overlap-style `ValueError`, worded per-unit as `resolve_units` already does for `groups`.
5. **Strata are the landmark partition, not a new `Strata.kind`.** `codes = np.unique(s_of_evaluation_rows, return_inverse=True)[1]` (`s_of_evaluation_rows` = `data.s` for `permutation_importance`, or the fold's test rows' `s` for LOCO scoring) is built once and wrapped as `_score.Strata("user", codes, n_strata, cond, n_bins)` — i.e., landmark strata reuse the S17 **user-strata code path verbatim** (`_score.labels`, `_strata.donors`, `_strata.n_singletons`, `_boot._resample_ids` need no landmark-specific branch at all), rather than adding a new `Strata.kind`. This works because `Strata("user", ...)` already means "one integer code per row, supplied by the caller" — landmark's `s` is exactly that, at the resolution the design demands (rows only exchange values with rows of the same landmark).
   - The public `strata=` keyword must be left at its shared default `"time"` (meaning, for a landmark estimator only, "use the model's own risk-set partition" — never the counting-process meaning, since every stacked row has `start == 0` and `"time"` binning on a constant column would collapse to one stratum, silently defeating the whole point) **or** explicitly `"landmark"` (an accepted alias, self-documenting, behaviourally identical to leaving the default). Any other value (`None`, an array, or any other string) → `ValueError` ("strata is fixed to the landmark partition for landmark estimators; pass 'time' (the default) or 'landmark'"). This is a plan-level reading of tvc-plan's terse "`strata=` other than `'landmark'` raises" (the literal wording would make the *default* call raise, which cannot be intended); recorded as a refinement, the way S17 refined Q8's "`·ΣN`" wording (review log).
   - `n_strata` is accepted but has no effect on a landmark dispatch (documented, not warned — unlike the counting-process case, there is no notion of "coarser landmark bins" to trade off, so a non-default value is not user error).
   - `conditional_on` crosses the landmark partition with `n_bins` quantile bins of the named columns exactly as `_score.labels` already does for any `Strata` kind (`extra = [_strata.bin_codes(X[:, c], st.n_bins) for c in st.conditional_on if c not in cols]`) — no change needed there either. A conditioning column may itself be `"landmark"`; that is *not* forbidden (conditioning on `s` is meaningful — e.g. the level-vs-history diagnostic never conditions on `s`, but a user comparing across follow-up time might), only permuting it is.
6. **Rows and prediction, `scoring="pe"` (default).**
   - `data = model._landmark_data(df)` (the existing `_LandmarkBase._landmark_data`, i.e. exactly `make_landmark_data` with the fitted model's own settings — the same call `_fit_forest` used, so the stacked rows reproduce the training design when `df` is the training frame, or a fresh stack when `df` is held-out data covering possibly-different landmarks/subjects). `Xe, ye, row_ids, s = data.X, data.y, data.ids, data.s`.
   - `w = _windows(model.forest_, windows)` and `null = _baseline_at(model.forest_, w)` — **reused verbatim** from `inspection.py`'s existing helpers, passing `model.forest_` (the fitted inner `SurvivalForestTV`/`CompetingRisksForestTV`, itself already fit with `layout="stacked"` on the reset clock) in place of the counting-process `estimator`. `model.forest_.event_times_[-1] <= model.horizon` always holds by construction (`make_landmark_data`'s row `stop = min(U, s+horizon) - s`), so `_windows`'s existing `windows[-1] > tau` check is exactly the "landmark stacks require `windows[-1] <= horizon`" rule tvc-design asks for — no new validation code.
   - Prediction callable mirrors `_heldout`'s pattern with `model.forest_` standing in for `estimator`: `forest = model.forest_.forest_` (the Rust engine); survival → `forest.predict_cumhaz(Xr, w, model.forest_.aggregate, n_jobs)`; CR → `forest.predict_cause_cumhaz(Xr, w, n_jobs)`.
   - `Evaluation(Xe, ye, start=data's implicit 0 array, ids=row_ids, windows=w, null=null, alpha=alpha, causes=model.forest_.causes_ if competing else None, cause=cause, predict=predict)` — `start` is `np.zeros(Xe.shape[0])` (every stacked row's `start` field is 0 by construction; `Evaluation.start` only feeds `_score.labels`'s dead `"time"`-kind branch, which landmark dispatch never reaches per decision 5, so its value is inert but must still be an array of the right shape for `unit_importance`'s indexing).
   - `intact = _score.score(ev, ye, H, ids=row_ids)`, then the **existing** `_score.unit_importance` loop over `units` from decision 4, exactly as S17. Nothing downstream of "have an `Evaluation` and a `Strata`" is landmark-specific.
7. **Rows and prediction, `scoring="brier"`/`"ibs"`** (design §3, "never as a pooled stacked-data IPCW" — a genuinely separate code path, new in `_inspection/_score.py`).
   - **Why not reuse `unit_importance`:** IPCW weights need a censoring model fitted *per landmark* on that landmark's own test outcomes (`model_selection._score_landmark`'s documented contract — pooling all stacked rows into one reverse-KM would let a subject's many landmark copies' censoring times leak across each other and would not match `landmark_cross_validate`'s own numbers, the equality tvc-design explicitly demands in §3). So scoring itself, not just permutation, must run one landmark at a time.
   - **Baseline:** for each `s` in `model.landmarks_`, `m = flatnonzero(data.s == s)`; `times = [model.horizon]` (`"brier"`) or `np.linspace(0, model.horizon, n_times + 1)[1:]` (`"ibs"`, the same grid `landmark_cross_validate` uses); `curve = model.forest_.predict_survival_function(Xe[m], times)` (survival) or `predict_cumulative_incidence(Xe[m], times, cause=cause)` (CR — `cause` is **required**, `ValueError` otherwise, tvc-design §6); `out = _score_landmark(curve, ye[m], model.horizon, {"brier": ...} or {"integrated_brier": ...}, times, censoring_estimator, g_min, cause)` (reused verbatim from `model_selection.py`, imported there — a private function made importable, or promoted to `model_selection.__all__`; decided in review as a plain import rather than a copy, since duplicating IPCW/censoring-fit logic is exactly the kind of drift tvc-design's "never... a pooled stacked-data IPCW" line is warning against).
   - **Pooling landmarks into one number** (a genuine design gap — tvc-design says "aggregate... as `landmark_cross_validate` does", but that function reports one row *per* landmark and never itself collapses them to a single score): the **n-weighted mean** of the per-landmark score, weight = that landmark's risk-set size (`out["n"]`, the same denominator `landmark_cross_validate`'s own rows already carry per landmark) — `pooled = sum_s n_s * score_s / sum_s n_s`. This is recorded as a plan-level resolution of an underspecified point (review log), analogous to S18's LOCO-pooling and §7.7b-margin resolutions; it is the natural choice because it is exactly the weighting `_score_landmark`'s own `info["n"]` already exposes, and it makes a landmark with more at-risk subjects count proportionally more, matching every other per-event/per-row pooling convention already in this codebase (`piecewise_exponential_score`'s `n_events` pooling; LOCO's `N` pooling).
   - **Importance and its sign:** Brier/IBS are losses (lower = better; `model_selection._SCORERS` already encodes `"brier"`/`"integrated_brier"`: `"min"`), the reverse of the PE score's "higher is better" convention every other part of `inspection.py` uses. To keep "importance > 0 means the unit matters" uniform across scoring families, **`importance = pooled(permuted) - pooled(baseline)`** for `scoring in {"brier", "ibs"}` (a positive number: permuting made the loss worse), the mirror image of PE's `intact - permuted`. This sign flip is stated once, in the docstring, next to the `scoring=` parameter — not silently baked into a shared subtraction helper that would need a comment to un-confuse a reader.
   - **Permutation:** the same `Strata("user", s_codes, ...)` and unit columns as decision 6; for a given unit and repeat, permute within each landmark's own risk set as in `_permuted` (reused: `_permuted` only needs `ev.predict`, `H`, `X`, `cols`, `lab`, so it is generic across scoring families already — the "H" it carries is whichever prediction the caller's `predict` produces, here the survival/CIF curve at the scoring grid rather than a cumhaz array) then re-score every affected landmark's risk set (only landmarks whose rows changed need a fresh `_score_landmark` call — a landmark none of whose rows were re-predicted keeps its baseline per-landmark score, an optimisation worth taking since IPCW censoring fits are the expensive part of this path).
   - **Bootstrap SE:** the same `_boot._resample_ids` (decision 9's id-cluster reuse) with the pooled-score statistic recomputed on the resampled rows (each landmark's own censoring re-fit on the resampled subjects' outcomes at that landmark, per `_score_landmark`'s existing contract).
   - **`share_of_gain`:** `None` for `scoring in {"brier", "ibs"}` — there is no training-null curve analogous to `baseline_cumhaz_` for Brier/IBS in this design, so the field is omitted (documented) rather than invented; PE's `baseline_score`/`null_score`/`share_of_gain` fields stay populated only for `scoring="pe"`.
8. **LOCO for landmark** (`_inspection/_loco.py` gains a landmark branch — not literally listed under S19's tvc-plan "Files" line, but required to have `drop_column_importance` dispatch at all for landmark estimators; recorded as a plan-level addition beyond the literal Files wording, the way S18 added `_split_checks`/`_disjoint_check` beyond its own Files line).
   - **Folds are not `_cv_folds`** (S18's review-log finding 1 stands: landmark rows are polars-frame-shaped, keyed by `s`/`groups`, not the `(X, y, ids)` triple `_cv_folds` iterates). A new `_inspection/_loco.py` function, `run_landmark(model, df, units, cv, ...)`, mirrors `landmark_cross_validate`'s own fold loop shape: `data = model._landmark_data(df)`; `for train_idx, test_idx in cv.split(data.s, groups=data.groups)`; `time_split = _split_checks(model.horizon, cv)` (the **shared** helper factored out in S18, reused as-is — this is the literal "shared with `landmark_cross_validate`" tvc-design/tvc-plan ask for, honoured at the checks level exactly as S18 already established); `_disjoint_check` otherwise; `df_train = df.filter(pl.col(model.id).is_in(np.unique(data.ids[train_idx])))`, censored via `_censor_at` at `data.s[test_idx].min()` under a time split (identical to `landmark_cross_validate`'s own lines — a second, near-verbatim copy of that fold-preparation logic, since `landmark_cross_validate` is not itself refactored into a shared "prepare one fold's training frame" helper in this slice; flagged for a possible follow-up, not fixed here, the same category of deferred refactor as S18's item 1).
   - **Per fold, per seed:** `full = clone(model).set_params(landmarks=train_s, step=None).fit(df_train)` (mirrors `landmark_cross_validate`'s own `fitted = clone(model).set_params(...).fit(df_train)`); windows/null (PE) come from `full.forest_` exactly as decision 6; **per dropped unit `j`** (a raw column name from `raw_groups`, or a user group's raw-column set): `dropped_features = [spec for spec in model.history_features if _feature_specs([spec], forbidden=set())[0][1] not in unit_columns_as_raw_names]` — i.e. `clone(model).set_params(history_features=[item for item in model.history_features if the item's raw column is not one of unit j's raw columns], landmarks=train_s, step=None).fit(df_train)`. A **user `groups=`** unit that names individual *feature* columns rather than whole raw columns (decision 4's `groups` branch permits this) drops exactly those `history_features` entries whose derived name is in the group — both cases reduce to "drop every `history_features` entry whose derived name is in this unit's column set", computed once by mapping `raw_groups`/`names` to `history_features` indices before the fold loop starts (not recomputed per fold).
   - Scoring on the test landmarks reuses decision 6 (PE) or decision 7 (Brier/IBS) with `full`/`dropped` fitted models in place of `model`, evaluated on `df.filter(ids in test)`'s stacked rows at the test landmarks only (`data.s[test_idx]`, `data.ids[test_idx]`, `Xe[test_idx]`, etc. — the *already-stacked* `data` from the top-level `df`, sliced by `test_idx`, not a fresh `make_landmark_data` call on a filtered frame, so train/test share one stacking pass and one `s` grid).
   - **`add_noise_control`:** draws one standard-normal value per **row of `df`** (not per stacked row — `rng.standard_normal(df.height)`, keyed by the shared entropy as S18), appended to `df` as a column `"_noise"` once, before any fold split, shared by every fold/seed (S18's "reproducibility of the column, not the fit"). The **full** model of every fold is fit with `history_features = list(model.history_features) + ["_noise"]` (agg `"last"`, matching S18's plain-column simplicity — no aggregation choice is being tested); the dropped-`_noise` clone is `model.history_features` unchanged (i.e. the ordinary "full" model of a *non*-noise-control run). `raw_groups`/`units` gain a `"_noise"` unit exactly as S18 appended a `"_noise"` column index.
   - **SE, pooling, cost guard, `n_jobs`:** unchanged from S18's decisions 6-10, with "id" meaning `model.id` values (a subject may appear in several test landmarks of the *same* fold — its `ΔS_i`/pooled-Brier contribution is summed over its landmark-copies within that fold before the id-cluster SE, mirroring `piecewise_exponential_score`'s own `by_id` accumulation over repeated rows of one id).
9. **Bootstrap SE reuse** (`permutation_importance`, both scoring families). `_boot._resample_ids(ev.ids, rng)` needs no landmark-specific code: it groups by whatever `ids` array it is given via `np.unique`, so passing `row_ids` (a subject id repeated once per landmark it is at risk at) already gives "a drawn copy carries **all** of that subject's landmark rows" for free (design §3's "the id-cluster bootstrap resamples **ids** (all landmark copies of an id move together)"), exactly as decision 5 made strata reuse free. `S17`'s existing bootstrap loop (`_score._bootstrap_se`) is reused verbatim for `scoring="pe"`; decision 7's Brier/IBS path reimplements the same resample-then-rescore shape with its own scoring call.
10. **CR** (tvc-design §6). `cause=None` (default) for `scoring="pe"` behaves as S17 (`importances_cause` populated, summed over causes for the total); for `scoring="brier"`/`"ibs"`, `cause` is **required** (`ValueError` "cause is required for Brier/IBS importance of a competing-risks landmark model" — there is no CR analogue of `piecewise_exponential_score`'s cause-summed total for a risk `F_k`, since summing cumulative incidences across causes is not itself a probability).
11. **Result `Bunch`.** Same fields as S17 for `scoring="pe"` (`importances`, `importances_mean`, `importances_std`, `importances_se`, `importances_window`, `window_edges`, `importances_cause`, `importances_id`, `id_labels`, `share_of_gain`, `baseline_score`, `null_score`, `zero_rate_share`, `n_events`, `n_truncated_events`, `n_unpermuted`, `feature_names`, `units`); `n_rows_excluded` is always 0 for landmark (no OOB path). For `scoring in {"brier", "ibs"}`: `importances`, `importances_mean`, `importances_std`, `importances_se`, `share_of_gain=None`, `baseline_score` (the pooled baseline loss), `feature_names`, `units`; `importances_window`, `importances_cause` (CR requires one `cause`, so there is nothing left to decompose by), `importances_id`, `zero_rate_share`, `n_truncated_events`, `n_unpermuted` are `None` (documented: those decompositions are PE-specific; no landmark Brier/IBS field pretends to have them). `drop_column_importance` mirrors this split of S18's `Bunch` the same way.
12. **Public surface.** No new exported names (`permutation_importance`/`drop_column_importance` already exported); `api.rst`'s existing `rftvc.inspection` section needs no new `autofunction` entries, only prose (deferred to S20's user guide per tvc-plan; this slice's `api.rst` touch is limited to the two functions' updated docstrings rendering correctly and `landmark.AGGREGATIONS`'s new entries appearing in `LandmarkSurvivalForest`'s `history_features` parameter doc, which already references `AGGREGATIONS` by value rather than listing it literally — checked, not edited).

## Simulations (T8; rules from design §7.2/§7.5b, predeclared)
Reuses the R = 50 / 10-rep-pilot convention of S17/S18 (`bench/tvc_landmark_sim.py`).

**Deviation (user-approved 2026-09-27): the §7.2 "history" rule stays failed-as-declared; the §19-plan does not change.**
- The generator's hazard depends on the *true* rolling 2-unit mean of `z` (`(z_{k-1} + z_k) / 2`), a deliberate mismatch with what the fitted model can see: `history_features=["z", ("z", "mean")]` gives the model `z`'s *cumulative* mean since the earliest known row, not a rolling 2-unit window (the framework's `"mean"` aggregation has no windowed variant — see decision 2/T1; adding one is out of scope for this slice).
- With `step=1.0` sweeping landmarks across the whole `k = 0..7` grid, the cumulative-mean proxy is a good stand-in for the true rolling-2 driver only at early landmarks (at `k = 1` it is literally the true value); at later landmarks it dilutes across many more points than the true driver's window (e.g. at `k = 7` the cumulative mean averages 8 draws against a true 2-draw window, correlation ≈ 0.5), so the average forest statistic over all landmarks is pulled below the 0.25× margin that assumed a closer proxy.
- This is a property of the deliberately-mismatched diagnostic (my own invention for this slice — tvc-design gives the qualitative scenario, not the exact 0.25×/0.05× numbers or the featurization detail), not a defect in `permutation_importance`'s landmark dispatch: the Markov control passes cleanly (confirming the conditional-permutation machinery correctly isolates "history matters" from "level matters" when the model's own feature *does* match the true driver, as it does in that scenario), and §7.5b's two landmark-specific checks both pass. Un-mismatching the fixture (e.g. restricting to later landmarks only, or lowering `K`) would very likely clear the 0.25× bar, but doing so now would be tuning the fixture to the result rather than reporting the predeclared rule's outcome; the user accepted this as a deviation rather than asking for the fixture/margin to be revisited.

## Review log (self-review; no external Codex session available this turn)
Findings from a full read of `tvc-design.md` §3/§5/§6/§7.2/§7.5b, `tvc-plan.md` S19, `landmark.py`, `inspection.py`, `_inspection/_units.py`/`_score.py`/`_loco.py`/`_boot.py`, `model_selection.py`, against this plan's decisions:
1. **`strata=` for landmark models is underspecified by tvc-plan's literal wording** ("other than `'landmark'` raises" would make the default call raise). Resolved (decision 5): the shared default `"time"` is silently reinterpreted as the landmark partition for landmark estimators, `"landmark"` is an accepted explicit alias, anything else raises. Recorded as a refinement of tvc-plan's wording, the same category as S17's Q8 refinement and S18's `_cv_folds`-sharing refinement.
2. **tvc-design's "aggregate... as `landmark_cross_validate` does" (Brier/IBS) has no literal single-number pooling rule** (that function returns one row per landmark and never itself collapses them). Resolved (decision 7): the n-weighted mean of the per-landmark score, using the same `n` `_score_landmark`'s own `info` already reports — a plan-level resolution, not a code-reading gap.
3. **Brier/IBS is a loss (lower is better); every other importance number in this codebase is "higher is better" (PE score, LOCO's PE drop).** Left implicit, this would silently invert the sign of "importance" for two of three `scoring` values. Resolved (decision 7): `importance = pooled(permuted) − pooled(baseline)` for Brier/IBS (the mirror of PE's `intact − permuted`), stated once in the docstring next to `scoring=`.
4. **`_score_landmark` is currently a private, unexported function of `model_selection.py`.** Reusing it from `_inspection/_score.py` needs either a plain cross-module private import (acceptable — both are internal modules of the same package, and `_inspection/_loco.py` already imports from `model_selection.py` for `RollingOriginSplit`/`_cv_folds` since S18) or promotion to a public name. Resolved (decision 7): a plain import, no promotion — nothing about `_score_landmark`'s contract needs to change for this reuse, and promoting it to public API is out of scope for a slice that only consumes it.
5. **LOCO's fold-preparation logic (`df_train`, `_censor_at`, `train_s`/`test_s`) duplicates `landmark_cross_validate`'s own lines a second time**, beyond the "shared checks" S18 already established. A shared "prepare one fold's training frame" helper would remove the duplication, but `landmark_cross_validate`'s loop also handles nested CV (`param_grid`/`inner_cv`) and prediction-recording (`return_predictions`) inline, so factoring it out cleanly is a larger, orthogonal refactor. Resolved: duplicated as decision 8 describes, flagged here as a possible follow-up (same category as S18's review-log item 1), not fixed in this slice.
6. **The `groups=` branch of `resolve_landmark_units` reuses `resolve_units`'s "is the ids column, not a feature" message for a `"landmark"` entry**, which is not quite the right words (`"landmark"` is not an ids column). Resolved: accepted as a small, documented wording debt (decision 4) rather than forking `_column`'s error text for one extra case — the *behaviour* (raise on `"landmark"`) is what tvc-design requires; the message text is a minor UX rough edge, not a correctness gap.
7. **§7.5b's "repeated landmark copies" and "heavy censoring" checks have no numeric margin in tvc-design** (§7.5b's own text: "repeated landmark copies of one id (importance and SE with `step` small vs large), and heavy censoring... vs the PE score"), unlike every other §7 item's explicit oracle-relative margin. Resolved (Simulations §2): two coarse, reported, non-tight pass conditions invented for this slice (a clustering-sanity SE ratio; a rank-concordance check across scoring families) rather than inventing a false-precision numeric bound; recorded plainly as this slice's own choice, not a design number, the same way S18 flagged its invented grouped-vs-single-copy bound as its own (later corrected) invention.
8. **`add_noise_control` for landmark LOCO needs a *row-level* raw covariate, not a per-`Xnum`-column noise vector like S18's** (a landmark model builds features from `df` via aggregation, so a per-stacked-row noise column would get "aggregated" nonsensically across a subject's known-at-`s` rows — e.g. a `"mean"` of independent noise draws is not the same random variable as any user would sensibly ask to test). Resolved (decision 8): one noise draw per `df` **row** (the same level every other raw covariate lives at), with a fixed `"last"` aggregation into `history_features`, the simplest choice that makes the noise control an ordinary raw column like any other.
