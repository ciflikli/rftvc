# S9: leaf-storage slimming at 1M rows

Generated by `bench/s9_leaf.py` (M-series Mac, 10 cores, 16 GB), same data and settings as
`bench/compare.py` (100 trees, leaf size 15, `max_features="sqrt"`, subsample 0.632, 10 threads).
`main` = before S9, `S9` = this slice. Forest bytes: `main` is the logical size of the old layout
(24 B per node, 96 B of `Vec` headers per leaf, 28 B per leaf event time; no
allocator or capacity slack, so a lower bound); `S9` is `forest_.nbytes` (exact: the arrays are
shrunk to fit). Both include one copy of the grid.

**Summary.**
- Forests are unchanged: the same leaves, event times and test C as on `main`. Predictions are bit-identical (checked on GBSG2, a TVC simulation and PBC2 landmark data, both `aggregate` values, exact and `ntime=50`, OOB included).
- Forest memory falls about 60%: 28 → 12 B per leaf event time, and no per-leaf `Vec` headers or allocations. Peak RSS at 1M rows falls from 2.0–2.3 GB to 1.5 GB (one row per id), and from 1.4 to 1.0–1.1 GB (TVC data).
- Pickles shrink less (23–31%), because node arrays (24 B per node) and `u64` leaf offsets are unchanged and now make up a larger share.
- Fit time is unchanged within noise (a few % faster: fewer allocations).
